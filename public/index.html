WHAT IS THE MAGI SYSTEM?

            

              MAGI is an autonomous multi-agent consensus system inspired by the supercomputer triad designed by Dr. Naoko Akagi in Neon Genesis Evangelion. Rather than relying on a single conversational LLM with unpredictable blind spots, MAGI distributes complex, high-stakes decisions across three differentiated cognitive personas who analyze, cross-examine, and arbitrate difficult dilemmas.
            

          


          

            

              

                MELCHIOR-1
                DR. AKAGI AS A SCIENTIST
              

              
PRIMARY COGNITIVE PROFILE: ANALYTICAL & OPTIMIZATION

              

                Focuses rigorously on structural performance, mathematical efficiency, architectural purity, and memory safety. Prioritizes state-of-the-art tooling (e.g. Rust, zero-cost abstractions, compiled speed) and eliminating latency overhead.
              

              

                COGNITIVE BIAS: May underestimate human engineering fatigue, organizational migration drag, and second-system syndrome.
              

            


            

              

                BALTHASAR-2
                DR. AKAGI AS A MOTHER
              

              
PRIMARY COGNITIVE PROFILE: RISK, DEFENSE & SURVIVAL

              

                Acts as the skeptical defense layer and existential risk sentinel. Scrutinizes catastrophic tail risks, developer burnout, production delivery halts, operational complexity, and vendor lock-in. Holds veto power through minority dissent reports.
              

              

                COGNITIVE BIAS: May exhibit excessive conservatism, risk aversion, and resistance to beneficial technological evolution.
              

            


            

              

                CASPER-3
                DR. AKAGI AS A WOMAN
              

              
PRIMARY COGNITIVE PROFILE: LATERAL & PRAGMATIC

              

                Focuses on realistic compromises, transitional architectural patterns (such as the Strangler Fig pattern), organizational viability, and synthesis. Breaches deadlocks between Melchior and Balthasar by formulating actionable, reversible paths forward.
              

              

                COGNITIVE BIAS: May favor tactical short-term viability over long-term architectural perfection.
              

            

          

        


        
        

          

            
EXECUTION STRATEGIES & TOKEN ECONOMICS

            

              MAGI treats execution strategy as a deliberate operational tradeoff between latency, cost, and epistemic independence.

HOW TO CHOOSE BETWEEN FAST AND FULL MODE:

            
    
              
  • Use FAST MODE when exploring ideas, running rapid benchmarks, experimenting with prompts, or operating under strict rate limits.
    • 
              
  • Use FULL MODE when making decisions that cannot be easily undone (irreversible migrations, critical security protocols, major cloud investments).
    • 
            

          

        


        
        

          

            
DATA PROVENANCE & RECORDING INTEGRITY

            

              MAGI strictly distinguishes between authentic production execution and scripted or demonstrative telemetry.
            

          


          

            

              

                LIVE DELIBERATION
                GENUINE API EXECUTION
              

              
Generated in real-time by configured LLM providers (Google Gemini 3.1 Pro, Groq Llama 3.3 70B, or local Ollama). Incurs actual token usage and latency.

            


            

              

                MOCK DEMONSTRATION
                ZERO API COST
              

              
Uses verified deterministic fixtures from the built-in offline mock store (e.g. Node.js to Rust migration). Completely offline and incurs zero API cost.

            


            

              

                OPERATOR OVERRIDE
                CONTROLLED SIMULATION
              

              
Triggered manually by an authorized operator via the Operator Cockpit to test animation playback, simulate network timeouts (504), rate limits (429), or record video demonstrations.

            

          


          

            
SIMULATED REPUTATION VS REAL METRICS:

            

              The Epistemic Reputation Matrix displays historical calibration scores (survival rates, vindications, and false alarm metrics). In public mock demonstration mode, this matrix is explicitly tagged with DEMO CALIBRATION to guarantee that synthetic data is never misrepresented as empirical production metrics.
